## 1. Design your profile

Open the [editor](https://gitascii.com/editor), load your GitHub username, and choose a [template](/templates/overview). Arrange widgets and adjust their properties. Editor changes are saved as a local browser draft; they do not update your public README until you publish.

## 2. Sign in and connect your repository

Sign in with GitHub. GitAscii also needs its GitHub App installed with access to your profile repository, `YOUR_USERNAME/YOUR_USERNAME`. OAuth sign-in identifies you; the App installation supplies the repository permissions used for publication.

If publishing opens the installation flow, return to the editor and publish again after granting access. The installation callback does not publish a profile by itself. If the repository is missing, the backend attempts to create it; if that fails, create your public profile repository on GitHub and give the App access to it.

<Warning>
  The current publisher replaces the repository's `README.md` with the generated embed. Save any
  existing README content before publishing, and restore your surrounding text afterward. This also
  applies when publishing later edits.
</Warning>

## 3. Publish to GitHub

Choose **Publish to GitHub**. GitAscii renders the first dark and light SVGs on its backend and writes:

| Location                  | Files                                                                      |
| :------------------------ | :------------------------------------------------------------------------- |
| `gitascii` branch         | `gitascii.json`, `profiles/default/dark.svg`, `profiles/default/light.svg` |
| Repository default branch | `README.md`, `.github/workflows/gitascii.yml`                              |

The README uses a `<picture>` with raw GitHub URLs. The first images do not depend on waiting for the scheduled Action. Open both SVG files on the `gitascii` branch and check the README. See [README integration](/guides/github-readme-integration) for the complete embed and named-profile paths.

## 4. Refresh data and publish changes

The installed GitHub Action refreshes the published images from saved configuration and current GitHub data. Editor publication requests a manual run; the generated workflow also has a daily Free or hourly Pro schedule. Pro scheduled publication is additionally limited by the configured refresh interval, so an hourly workflow does not necessarily produce an hourly commit.

To refresh manually, open your repository's **Actions** tab, select the GitAscii workflow, and use **Run workflow** on the default branch. To change the design, edit it in GitAscii and publish again. Editing a JSON file directly on `gitascii` does not trigger the workflow: dispatch it or wait for its schedule.

Continue with [using the editor](/guides/editor), [GitHub Action and refreshes](/guides/github-action), [troubleshooting](/guides/troubleshooting), or the detailed [V1 and V2 architecture](/architecture/rendering-and-publishing). Developers can [render a configuration locally](/guides/reproduce-editor) or follow [development and deployment](/guides/development).
