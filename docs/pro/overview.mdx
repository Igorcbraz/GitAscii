# GitAscii Pro

GitAscii Pro extends v2 publishing with multiple profiles, versions, dynamic rules, publication health, error alerts, and analytics for a separate README badge. The normal profile SVG is hosted on the user's `gitascii` branch; visiting the README does not call GitAscii's rendering service.

```text
Editor → gitascii branch: configurations + dark/light SVGs
        → GitHub Action refreshes SVGs → optional OIDC health report
README → raw.githubusercontent.com profile SVGs
       → optional gitascii.com/api/badge/username → badge request metrics
```

## Pro features

| Feature               | What it measures or controls                                                                                                                      |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| Profiles and versions | Publish named profile slugs, duplicate designs, inspect revisions, and restore a saved version.                                                   |
| Dynamic rules         | Choose a profile for the default **HTTP API** embed when `?dynamic=1` is enabled; static raw GitHub URLs do not switch at request time.           |
| Analytics             | Counts requests observed by the separate badge endpoint, usually GitHub Camo cache refreshes. These are not exact human views or unique visitors. |
| Health and errors     | Receives authenticated GitHub Action reports about publication runs and failed external assets. The health badge displays that reported state.    |
| Alerts                | Can send email for reported widget or asset failures, subject to settings and cooldown.                                                           |

The dashboard routes include `/pro`, `/pro/analytics`, `/pro/health`, `/pro/profiles`, `/pro/reports`, `/pro/errors`, and `/pro/emails`.

## Storage and trust boundaries

When `DATABASE_URL` is configured, PostgreSQL stores persistent profile and Pro data; Redis supports caches and some telemetry operations. Without a configured database, Redis is used for several stores, with an in-memory development fallback. GitHub remains the source of the published configuration and SVG files. The GitHub App token authorizes publication; the Action sends Pro health reports using a verified GitHub OIDC token.

For the limits of analytics, see [Telemetry & Privacy](/pro/telemetry-and-privacy). For README embeds, see [GitHub README Integration](/guides/github-readme-integration).
