The canonical TypeScript model is [SavedConfiguration](/api/configuration). V2 stores the default profile as `gitascii.json` on the `gitascii` branch, and named profiles as `gitascii_[slug].json`. The Action reads those files to render `profiles/[slug]/dark.svg` and `light.svg`.

## Editor download versus published configuration

The toolbar's JSON export contains `widgets`, `globalStyles`, and `templateId`. It is a portable **layout export**, not necessarily a complete `SavedConfiguration` with identity, slug and metadata.

The publication request also supplies the username and profile slug; the backend assigns revision/update metadata. If consuming a downloaded layout in code, start with `createConfiguration` and overlay its layout fields. Do not assume a TypeScript cast fills missing values.

The [local rendering example](/guides/reproduce-editor) accepts both a layout export and a complete configuration. Its [sample configuration](https://github.com/Igorcbraz/GitAscii/blob/main/docs/examples/profile-config.json) contains one native stats widget and no remote assets. The paired data file uses invented fixture values, not live GitHub metrics.

## Which copy is used?

| Copy                      | Consumer                                                                                                                               |
| :------------------------ | :------------------------------------------------------------------------------------------------------------------------------------- |
| Browser draft             | Editor state before publication.                                                                                                       |
| App configuration storage | Editor/API and Pro profile management. PostgreSQL when configured, otherwise Redis for configuration persistence, plus memory caching. |
| JSON on `gitascii`        | GitHub Action refresh input and preferred source for the public configuration endpoint.                                                |
| Published SVG             | README image delivery; no database read is needed to serve it.                                                                         |

A direct GitHub JSON edit does not synchronize the database or trigger the generated workflow. A later editor publication can replace that JSON with the current editor design. Keep these sources consistent when mixing manual edits and the web app.

For compatibility, configuration loading also checks legacy locations on `main` and `master`. These are fallbacks, not the normal V2 publishing destination. See [architecture](/architecture/rendering-and-publishing) for lookup order and migration details.

## Fetch a saved profile

```http
GET https://gitascii.com/api/config/USERNAME/default
```

The public route prefers GitHub configuration and returns `404` when it cannot find the requested profile. It does not publish or run the Action. See [HTTP endpoints](/reference/endpoints).
