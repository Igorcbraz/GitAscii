title: 'Rendering Engine'
description: 'The shared SVG engine used by the backend and GitHub Action'
---

The engine in `src/engine/` converts a configuration and GitHub data into SVG. Initial publication runs on the GitAscii backend; scheduled refreshes run in GitHub Actions. Standard README visits load the resulting files from GitHub. See [architecture](/architecture/rendering-and-publishing) for the complete flow.

`@/engine` is an internal repository alias, not an independently published SDK. Examples using it run inside a GitAscii checkout. The [local rendering guide](/guides/reproduce-editor) includes an executable example.

## Render a composition

```typescript
import { renderSvg } from '@/engine'

const svg = renderSvg(config, githubData, { theme: 'dark' })
```

`renderSvg(config, data, options)` normalizes input data, filters visible widgets, sorts by `zIndex`, and wraps widget markup in a root SVG.

| Option            | Implemented behavior                                                                                                                                    |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `theme`           | Selects the root dark or light background. Widget colors still depend on their configuration and renderer; this does not recolor every hardcoded color. |
| `width`, `height` | Override canvas bounds. Normal rendering uses an 800-pixel width and content-derived height.                                                            |
| `widgets`         | Filters by widget or instance ID and repositions selected widgets to shrink-wrap the output.                                                            |

The type also declares `embedFonts` and `optimize`, but the current `SVGEngine` does not consume these options. Do not rely on them for font embedding or optimization. Font appearance can differ between editor previews and image viewers.

## Render a widget fragment

```typescript
import { renderWidgetSvg } from '@/engine'

const fragment = renderWidgetSvg(widget, githubData, globalStyles, true, false)
```

The last arguments are `includeWrapper` and `forceStatic`. This returns an SVG **fragment**, normally inside a positioned `<g>`, not a standalone image. Use `renderSvg` with a one-widget configuration to obtain the root SVG. The wrapper adds frames, decorations and configured entrance animation; some renderers supply their own frame. Support for `forceStatic` depends on the registered renderer.

## Process external assets

```typescript
import { processExternalAssets } from '@/engine'

const result = await processExternalAssets(svg)
// result.svg, result.hasErrors, result.failedUrls (when available)
```

The publishers run this separate asynchronous stage before committing files. It resolves external-widget markers and remote images, validates fetch targets, sanitizes supported SVGs, and embeds raster data with its MIME type. `embedExternalImages` remains an alias for this function.

A failed asset may become a fallback or placeholder while the rest of the SVG is published. Check `hasErrors` and `failedUrls`; a returned string alone does not mean every dependency succeeded. See [external widgets](/widgets/external-widgets) and [publication health](/pro/health-monitoring).
