These instructions run inside a GitAscii checkout with its existing dependencies installed. `@/engine` is the repository's TypeScript alias, not a separately installable SDK. The example is a Node script; it is not a claim of compatibility with every edge runtime.

## Run the offline example

From the repository root:

```bash
npm exec -- tsx docs/examples/render-profile.ts docs/examples/profile-config.json docs/examples/profile-data.json
```

The script writes `scratch/docs-render/dark.svg` and `light.svg`. The sample uses a single stats widget and fixture data, so it does not need GitHub credentials or remote assets. Inspect both files in a browser.

Source: [render-profile.ts](https://github.com/Igorcbraz/GitAscii/blob/main/docs/examples/render-profile.ts), [configuration](https://github.com/Igorcbraz/GitAscii/blob/main/docs/examples/profile-config.json), [fixture data](https://github.com/Igorcbraz/GitAscii/blob/main/docs/examples/profile-data.json).

## Render your own layout

1. Download the editor's JSON layout, or obtain the complete configuration from your `gitascii` branch.
2. Supply a JSON file matching `NormalizedGitHubData`. The public `GET /api/github/USERNAME` route supplies GitHub profile data; fixture data is useful for reproducible local work.
3. Pass both paths to the same script, optionally followed by an output directory.

```bash
npm exec -- tsx docs/examples/render-profile.ts my-layout.json my-github-data.json scratch/my-profile
```

The script creates a base configuration, overlays the input, renders both themes, and runs `processExternalAssets`. Unlike the publisher's tolerant asset fallback, this example stops when asset processing reports errors, so they are visible during local verification. Configurations with remote images require network access.

This does not commit files, install a workflow or publish to GitHub. Use the editor's publishing flow for those steps.

## Preview differences

The editor and publishers share renderer code, but data freshness, browser fonts, stored ASCII grids and image-viewer behavior can differ. SVG fragment examples in widget pages assume `profileData` and `globalStyles` are already supplied; `renderWidgetSvg` does not produce a standalone SVG root. See [rendering](/api/rendering) and [data/display limits](/reference/data-sources).
